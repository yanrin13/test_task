
# Тестовое задание
форма бронирования с валидацией данных, выбором даты и времени, количеством гостей и экраном подтверждения

# Ссылка на проект
[test-task-dun.vercel.app](https://test-task-dun.vercel.app/)

## Запуск проекта


Установить зависимости:
```
npm install
```
Запустить проект в режиме разработки:
```
npm run dev
```

# Тестирование

Для тестирования используется Vitest

Установить Vitest
```
npm install -D vitest
```
Запустить тесты:
```
npm test
```

Для большей наглядности и покрытия функций для каждой тестируемой функции предусмотрены позитивный и негативный сценарии

Для управления состоянием бронирования используется Pinia
Переключение между формой бронирования и экраном подтверждения реализовано через булевый стейт. Выбрано т.к. это быстрое и простое решение

Логика валидации вынесена в отдельный composable, чтобы отделить проверку данных от компонента формы

также я решила сократить себе валидацию на уровне верстки, ограничив количество гостей четными числами и диапазоном, чтобы 1. конечный пользователь не вводил числа вручную с клавиатуры 2. для сокращения валидации

с номером телефона я решила этого не делать, потому что посчитала что это будет долго и валидировать будет нечего. в реальном проекте, мне кажется что удобнее для конечного пользователя и легче для валидации было бы обозначить 10 квадратных инпутов в строчку для цифр номера телефона и +7 вначале

А еще я решила стилизовать форму под чек т.к. я думаю это подходит тематике :)
